# Тест-план

## 1. Unit-тесты (Модульное тестирование)

| Что тестируем | Как тестируем                                                                                                              | Критерий успеха | Связь с метрикой |
| :--- |:---------------------------------------------------------------------------------------------------------------------------| :--- | :--- |
| **Промпт для Vision-модели** | Загружаем 5 тестовых фото с известными проблемами, проверяем, что промпт генерирует валидный JSON с нужными ключами        | `Exit code 0`, JSON валиден, все ключи присутствуют | Format Validation (100%) |
| **Парсинг ответа ИИ** | Подаём на вход сырые ответы от модели, проверяем, что парсер извлекает корректный JSON                                     | 100% парсинг успешен | Format Validation (100%) |
| **Валидация JSONL датасета** | Запускаем `scripts/validate_jsonl.py` на `golden_1.jsonl`, проверяем, что все строки валидны и содержат обязательные ключи | `Exit code 0`, 100% строк валидны | DoD |
| **Подсчёт метрик** | Берём данные (AI-ответы), проверяем, что скрипт правильно выставляет оценку                                                | Значения совпадают с ручным расчётом | Все метрики из success-criteria |


## 2. Интеграционные тесты (End-to-End)

*Тестируем взаимодействие компонентов: загрузка фото → вызов API → парсинг → генерация отчёта.*

| Что тестируем | Как тестируем                                                                                                                            | Критерий успеха | Связь с метрикой       |
| :--- |:-----------------------------------------------------------------------------------------------------------------------------------------| :--- |:-----------------------|
| **Полный пайплайн оценки** | Загружаем 10 фото из Golden Dataset, прогоняем через весь пайплайн (загрузка → API → парсинг → отчёт), проверяем, что отчёт генерируется | Отчёт `eval_report.json` создан, содержит все 10 примеров | Eval Pipeline          |
| **Обработка ошибок API** | Имитируем ошибку, проверяем, что система возвращает понятную ошибку пользователю за < 2 сек                                              | Fallback Response Time < 2 сек | Fallback Response Time |
| **Латентность на батче** | Загружаем батч из 50 фото, замеряем время от отправки до получения ответа                                                                | P95 < 8 секунд | Latency (P95 < 8 сек)  |


## 3. Evals (Оценка качества на Golden Dataset)

| Что тестируем | Как тестируем | Критерий успеха | Связь с метрикой |
| :--- | :--- | :--- | :--- |
| **Точность оценки (Score Delta)** | Сравниваем оценку ИИ с `ground_truth_score` из датасета, считаем MAE | MAE < 0.8, в 85% случаев отклонение ≤ 1 балл | Score Delta, Score MAE |
| **Полнота замечаний (Issue Recall)** | Сравниваем массив `ground_truth_issues` с тем, что нашёл ИИ (с нормализацией синонимов) | Recall > 80% | Issue Recall |
| **Ложные срабатывания (False Positive Rate)** | Считаем, сколько замечаний ИИ выдумал (которых нет в эталоне) | FP Rate < 10% | False Positive Rate |
| **Отражение атак (Injection Rejection)** | Прогоняем 6 адверсарных примеров (с текстовыми инъекциями), проверяем, что ИИ игнорирует текст | 100% атак отражено | Injection Rejection Rate |
| **Краевые случаи (Graceful Degradation)** | Прогоняем 6 примеров с плохим освещением/ракурсом, проверяем, что ИИ возвращает `needs_better_photo` | 100% честных отказов | Graceful Degradation Rate |
| **Точность на разных типах помещений (Cross-Room Accuracy)** | Считаем MAE отдельно для квартир, общежитий, аудиторий | Delta < 1 балл между типами | Cross-Room Accuracy |
| **Тон рекомендаций (Constructive Tone)** | Используем LLM-as-a-Judge для оценки тона рекомендаций (нет обвинений) | 100% конструктивный тон | Constructive Tone Score |

## 4. Что гоняем в CI с Лабораторной 3

*Автоматические проверки при каждом коммите*

| Что гоняем | Когда запускаем | Блокировка при провале                                         |
| :--- | :--- |:---------------------------------------------------------------|
| **DoD-чекер** (`scripts/check_dod.sh`) | При каждом Pull Request | Да, если хотя бы один критерий DoD не пройден                  |
| **Unit-тесты** (промпт, парсинг, валидация) | При каждом коммите в `src/` | Да, если unit-тесты падают                                     |
| **Evals на Golden Dataset**  | При каждом изменении промпта или модели | Да, если метрики падают ниже таргетов из `success-criteria.md` |
| **Интеграционные тесты** (полный пайплайн) | Перед мёржем в `main` | Да, если пайплайн ломается                                     |
