# Отчёт по DELIVERY для ЛР3

## Что подготовлено

- Подключён прототип на HTML/CSS/JavaScript к FastAPI: загрузка фото,
  состояние ожидания, показ результата и обработка ошибок.
- Добавлен `POST /inspection` с проверкой формата и ограничением размера
  файла до 10 МБ.
- Добавлено сохранение метаданных проверки и рекомендаций в PostgreSQL.
  Исходные байты изображений не сохраняются.
- Добавлена миграция `0002_prototype_inspections.sql`; Compose применяет
  миграции перед запуском API.
- Docker-образ включает файлы прототипа. В CI добавлен запуск тестов API.

## Что было исправлено при интеграции

- UI ранее только переключал статические состояния и не отправлял запросы.
- FastAPI ранее не раздавал UI и не имел эндпоинта загрузки фото.
- Стартовое Compose-описание не применяло миграции автоматически.
- В схеме не было полей для ID помещения/сотрудника, типа оценки и хранения
  результата веб-прототипа.

## Проверка и ограничения

Тесты API проверяют отдачу UI, загрузку, обработку ошибок и лимит размера.
Дополнительно миграции были применены к PostgreSQL, после чего запрос
`POST /inspection` сохранил результат и рекомендацию в БД. Локальный запуск:
`docker compose up --build`.

Оценка в `src/vision/analyze.py` — явно помеченная заглушка
(`model_used=demo-stub`, `is_demo=true`), а не результат анализа
изображения. Telegram webhook пока только подтверждает получение события.
Проверка полной сборки прошла успешно, но в этом окружении миграционный
контейнер не смог подключиться к PostgreSQL по внутренней сети Docker
(TCP timeout); миграции и API с PostgreSQL проверены отдельно через
опубликованный порт. Публичный URL из README ответил HTTP 503; выкатить
изменения на Render без доступа к проекту/деплойным секретам нельзя.
