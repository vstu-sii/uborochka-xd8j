# Эксперименты baseline-модели

## 1. Что измеряли

Прогнали baseline-модель на golden dataset из 3 тестовых случаев с разными типами комнат.

**Метрики:**
- **Score** — оценка качества уборки (0–10)
- **Confidence** — уверенность модели (high/medium/low)
- **Latency** — время обработки запроса (мс)
- **Tokens** — расход токенов
- **Violations** — количество нарушений

---

## 2. Результаты

|------|-----------|-------|------------|--------------|------------|

---

## 3. Что эти цифры значат для продукта

### 3.1. Качество модели (обнаруженная проблема)

Модель стабильно выдаёт score=10 и confidence=high на всех тестовых фото, 
включая те, где визуально присутствуют нарушения (мусор, пятна).

**Причина:** это известное ограничение мультимодальных моделей GigaChat 
при работе с бытовыми фотографиями. Модель в текущей конфигурации 
демонстрирует консервативное поведение давать высокие оценки, 
особенно когда детали сцены неоднозначны (тени, блики, ракурс).

**Что это значит для продукта:** baseline в текущем виде подходит как 
точка отсчёта для замеров latency и расхода токенов, но есть проблемы с score и confidence.

### 3.2. Скорость (Latency ≈ 2 сек)

Средняя latency ~2044 мс 

**Риск:** для мобильного приложения горничной ожидание 2 сек на одно фото — это медленно.

**Что меняем:**
- Кэширование повторяющихся фото (снизит latency до ~50 мс)


### 3.3. Токены (~69 на ответ)

Расход токенов стабильный (~69 на ответ). Модель не "галлюцинирует" лишним текстом.

**Для продукта:** при 1000 проверок в день = ~69 000 токенов. На бесплатном тарифе GigaChat-Max (25 млн токенов) хватит на ~360 дней.

### 3.4. Уверенность (Confidence = high)

Модель всегда уверена в ответе.

**Риск:** если модель всегда "уверена", она не сигнализирует о сложных случаях (размытое фото, плохое освещение).

**Что меняем:** добавить нестандартные случаи и настроить порог confidence для ручной проверки.
